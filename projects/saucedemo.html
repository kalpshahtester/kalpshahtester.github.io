Project overview

SauceDemo provides a representative shopping journey that makes it possible to exercise authentication, product discovery, cart behaviour and checkout interactions. The project was approached as an end-to-end manual testing exercise with attention to both expected flows and failure paths.

Testing scope

  • Login and authentication behaviour, including applicable demo-user paths.
  • Product listing, product details and navigation.
  • Adding, removing and reviewing items in the shopping cart.
  • Checkout journey and input validation.
  • Positive and negative paths across the customer flow.

Test approach

The work follows a traceable manual QA cycle: understand the requirements, identify scenarios, prepare test cases, execute and record outcomes, document reproducible defects, then retest and consider regression impact.

  • Use clear preconditions, steps and expected results.
  • Cover valid inputs as well as invalid, missing and boundary conditions where relevant.
  • Capture execution evidence and keep test records organised.
  • Write defects so another person can reproduce the observed behaviour.

Available project evidence

The repository contains project documentation including requirements/HLR, test planning, scenarios, test cases, execution evidence, defect reporting, a Requirements Traceability Matrix (RTM) and a test summary.

The metric totals above are taken from the project brief. Individual defect counts are intentionally not advertised here; the public project repository is the source for reviewing defect records and their definitions.

Scope and transparency

This is a portfolio project against a demo application. It should not be interpreted as testing performed for a production client, nor as evidence of production system access. The published repository should be used to inspect the actual artefacts and execution records.

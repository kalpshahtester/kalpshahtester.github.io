01PROJECT OVERVIEW

Quality across the
shopping flow.

SauceDemo provides a representative shopping journey that makes it possible to exercise authentication, product discovery, cart behaviour and checkout interactions. I approached the work as an end-to-end manual testing exercise, paying attention to the expected path as well as failure conditions and edge cases.

✳

The objective was not simply to confirm that the happy path works. It was to make the test coverage clear, reproducible and traceable from requirement through execution.

02TESTING SCOPE

What I set out
to validate.

01

Authentication

Login behaviour, applicable demo-user paths and unsuccessful authentication attempts.

02

Product discovery

Product listing, product details, sorting and navigation behaviour.

03

Cart behaviour

Adding, removing and reviewing items, plus checking that cart state stays understandable.

04

Checkout

Checkout progression, required fields, input validation and alternate paths.

  • Positive and negative test paths across the customer flow.
  • Missing, invalid and boundary inputs where relevant.
  • Navigation, repeat actions and state changes.

05SCOPE & TRANSPARENCY

Clear about
what this proves.

This is a portfolio project against a public demo application. It is not presented as production client work, production-system access or employment by SauceDemo. The metrics above describe project documentation and execution records; they are not a claim about production test coverage.

Individual defect totals are intentionally not promoted here. The public repository is the source for reviewing actual defect records and their definitions.

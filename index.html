My focus is manual testing across WordPress websites and web applications: functional behavior, responsive layouts, forms, navigation, content quality, and SEO-related checks.

I care about more than finding a bug. I want the report to be easy to reproduce, the impact to be understood, and the fix to be verified without creating another problem.

Before moving into QA, I supported more than 100 users in IT. That experience shaped how I troubleshoot, prioritize, and explain technical issues.

04 / QA WORKFLOW

A method that makes
quality visible.

A repeatable workflow keeps coverage traceable, defect follow-up clear, and releases more predictable.

01 / Understand

Clarify the goal

Review requirements, user stories, acceptance criteria, and risk areas.

02 / Design

Plan coverage

Prepare scenarios, cases, test data, and traceability.

03 / Execute

Explore behavior

Run positive, negative, boundary, and exploratory checks.

04 / Report

Explain the defect

Capture reproducible steps, impact, and evidence.

05 / Verify

Retest and regress

Check the fix and related journeys before sign-off.

06 / Summarize

Share status

Record outcomes, risks, and coverage status.

07 / Collaborate

Keep it actionable

Coordinate follow-up and communicate clearly with the team.

08 / Improve

Learn from findings

Use recurring defects to strengthen future test coverage.
